# TRADING HQ — Complete Website Development Specification

## 1. Project Overview

I want to build a personal trading journal and analytics platform called **TRADING HQ**.

This must be a fully functional, private website designed for my personal trading journey. It should help me record every trade, analyze my performance, understand my mistakes, identify patterns and improve my trading over time.

I also want an integrated AI assistant that can access and analyze the actual information stored in my website. I should be able to ask questions about my trading history in natural language and receive answers based on my real data.

The platform must be designed with future integrations for:

- **Lucid Trading** — my intended prop firm.
- **Tradovate** — the platform I intend to use for executing my actual trades.
- **TradingView** — for chart analysis, alerts and potentially sending trade-related information.

I am currently learning and backtesting. Therefore, the website must work perfectly without any external integrations initially. I want to be able to add integrations later without rebuilding the entire application.

This is a personal project, not a commercial product. Prioritize functionality, reliability, simplicity, privacy and accurate analytics over unnecessary features.

## 2. Technology and Development Requirements

Preferred technology:

- Frontend: React / Next.js or another suitable modern framework.
- Styling: Tailwind CSS.
- Backend and database: Supabase.
- Authentication: Supabase Auth.
- File and screenshot storage: Supabase Storage.
- AI: Secure server-side integration with an appropriate AI API.
- Hosting: A suitable low-cost or free hosting solution.

The developer can recommend alternatives if they are technically better.

### Important requirements

1. Build a real application, not a static visual mockup.
2. Every button, form, filter, chart, upload and navigation element must work.
3. Store information in a real database.
4. Implement authentication so my trading data is private.
5. Use proper database security and Row Level Security (RLS).
6. Never expose API keys, passwords or secret credentials in frontend code.
7. Make the application responsive, but prioritize desktop usage.
8. Include data export and backup functionality.
9. Avoid unnecessary paid services wherever possible.
10. Design the database and backend so future integrations can be added without major architectural changes.

Start with the simplest functional version and develop it in stages.

## 12. AI Trading Assistant

This is one of the most important features.

I want an AI assistant directly inside the website.

It should be able to access my actual journal, daily preparation, screenshots, trading statistics, account information and knowledge base, subject to my permissions.

I want to communicate with it naturally, just like I communicate with ChatGPT.

### Example questions

- Analyze my last 30 trades.
- What are my biggest recurring mistakes?
- Why am I losing more money on MNQ than MES?
- What do my best trades have in common?
- Which trading session is most profitable for me?
- Am I following my trading plan?
- Compare my last two weeks.
- Show me my most successful setups.
- Do I perform better on long or short trades?
- What happens when I enter without waiting for displacement?
- Analyze my daily bias accuracy.
- Compare my original daily analysis with what actually happened.
- Find examples of my best FVG trades.
- What should I focus on improving based on my recent performance?

### AI capabilities

The assistant should:

1. Retrieve relevant records from the database.
2. Calculate statistics using actual trade data.
3. Analyze patterns and recurring mistakes.
4. Compare different periods.
5. Analyze screenshots when supported by the AI model.
6. Reference specific trades when explaining its conclusions.
7. Use my knowledge base and personal rules as context.
8. Remember the context of the current conversation.
9. Support follow-up questions.
10. Explain its reasoning clearly.

### Accuracy requirements

This is extremely important.

The AI must never invent trades, statistics, screenshots or account information.

It must distinguish between:

- Verified facts from my records.
- Calculated statistics.
- Possible interpretations.
- Recommendations.
- Insufficient data.

If I have only five trades, it should not confidently claim that a particular strategy is profitable.

When answering statistical questions, it should show the relevant sample size and period.

The assistant should be focused on analyzing my trading behavior and performance, not simply giving generic trading advice.

### AI data architecture

Do not simply give the AI unrestricted database access.

Build a secure backend that retrieves the necessary records and performs calculations before providing relevant context to the AI.

The AI should have access only to the information required for the question.

Keep API keys on the server.

Track AI usage and make it possible to limit usage to control costs.

## 14. Data Accuracy and Trading Calculations

Accuracy is critical.

Build a reliable calculation engine for futures trades.

Do not hardcode one instrument's contract specifications into every calculation.

Store configurable instrument specifications, including:

- Tick size.
- Tick value.
- Point value.
- Contract multiplier.
- Commission structure.
- Other relevant fees.

For example:

MNQ has a $2 value per index point per contract.

If I trade 2 MNQ contracts and capture 20 points, the gross profit should be:

2 contracts × 20 points × $2 = $80 gross profit.

Fees must then be deducted to calculate net profit.

Make instrument specifications editable so I can update them if necessary.

Test all calculations with known examples.

Also ensure:

- Partial exits are calculated correctly.
- Multiple entries are calculated correctly.
- Fees are not deducted twice.
- Deposits and withdrawals do not distort trading performance.
- Imported trades are not duplicated.
- Account balances reconcile with available source data.
